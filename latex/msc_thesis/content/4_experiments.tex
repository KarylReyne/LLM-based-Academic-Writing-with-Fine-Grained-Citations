\section{Evaluation Methodology}
The main focus of this thesis is it to determine how the use of the passage retrieval module affects the retrieval accuracy and generation quality of ScholarCopilot. ScholarCopilot retains its original backbone model \mono{Qwen2.5-7B} \cite{an2024qwen2}. Since the retriever of the passage retrieval module is implemented with Batched Self-Consistency, it is required to follow multiple permutations of the same instruction during inference reliably and consistently (see \cite{korikov2025batched}). Instruction tuned models, that is, LLMs that are fine-tuned on (\mono{instruction}, \mono{desired-output}) pairs, are more successful at following instructions closely rather than just minimizing the next token prediction error \cite{shengyu2025instruction}. To make use of this, the PR module uses the instruction-tuned variant of the Qwen2.5 model, \mono{Qwen2.5-7B-Instruct} \cite{an2024qwen2}, as the passage retriever. Even though it has been shown that instruction tuned models may not fully utilize given instructions and are instead just good at learning the specified output format \cite{kung2023followInstructions}, this ability alone is valuable enough for the automated parsing of an LLMs' response to justify using an instruction tuned model (especially when using Batched Self-Consistency which greatly increases the number of responses that need to be parsed). 

With ScholarCopilot as baseline, I evaluated the impact of using the PR module on the retrieval performance for a variety of retrieval contexts. To this end, I introduce the \emph{single-step retrieval} task which aims to assess the models accuracy when resolving a single \mono{[RET]} token during generation. This task closely follows the evaluation methodology used by \cite{wang2025scholarcopilot}. For each of the section groups (\mono{IntroductionAndRelatedWork}, \mono{Methods}, \mono{Experiments}, and \mono{Conclusion}), $1$k randomly selected samples are used for the evaluation. Single-step retrieval is evaluated using the Recall@$k$ metric, which is given as the fraction of cases where the ground truth document appears in the top-$k$ retrieved documents \cite{wang2025scholarcopilot}. As outlined in \refsec{dataset}, the model is given the left-hand context of a citation drawn from an existing paper, together with the cited document as the ground truth. A retrieval token is appended to this context before the resulting sequence is passed to ScholarCopilot, causing the model to compute a representation of the \mono{[RET]} token based on the given context. This representation is then used to compute a distribution over the ScholarCopilot retrieval corpus that measures the relevance of each document in the corpus to the given context. When evaluating standart ScholarCopilot, the $k$ most relevant documents according to this distribution are compared to the ground truth, otherwise the top-$k_{SC}$ most relevant documents are passed to the passage retrieval module (for the reported results I use $k_{SC}=2k$, see also \refsec{hyperparameters}). For each of the top-$k$ ranked passages the PR module returns the document from which each passage was taken. These $k$ documents are then compared to the provided ground truth. Additionally, I evaluated two different strategies for replacing other citations that appear in the citing context. Other citations are either (1) masked using a \mono{[MASK]} token, this is also how \cite{wang2025scholarcopilot} handle citations, or (2) replaced with the abstract of the cited paper, which is done to imitate the generated context the retriever would be given during inference when the model encounters a \mono{[RET]} token. The datasets that use these replacement strategies are denoted as \mono{masked} and \mono{with-abstracts} respectively. Following the setup in \cite{wang2025scholarcopilot}, the given citing context is not truncated when passed to ScholarCopilot.\footnote{\cite{wang2025scholarcopilot} only use the last sentence of the context when evaluating their baseline models (\mono{BM25} and \mono{E5-Mistral-7B-Instruct}) but use the full context when evaluating ScholarCopilot.} However, I found that passing the entire context to the PR module reduces performance, thus only the last $w$ tokens of the citing context are used when the PR retriever is prompted to rank a given set of passages. See \refsec{passage-retrieval-instruction} for the detailed passage retrieval instruction.

% which generation model?
Since using human experts to evaluate the quality of LLM answers is costly and slow \cite{heineking2025ranking}, the quality of the generated academic text is evaluated using \mono{DeepSeek-R1-Distill-Qwen-7B} \cite{guo2025deepseek}. Following the setup in \cite{wang2025scholarcopilot}, the evaluating model (judge) is instructed to compare academic text generated by either ScholarCopilot or ScholarCopilot with passage retrieval to the ground truth document (which is the beginning of a scientific paper from arXiv, see \refsec{dataset}). It is instructed to evaluate the given generated text according to the five dimensions \mono{Content Relevance}, \mono{Logical Coherence}, \mono{Academic Rigor}, \mono{Background Completeness} and \mono{Innovation Statement}, see \refsec{generation-evaluation-instruction} for the detailed instruction.\footnote{It is intentional that I don't go into detail on how these categories should be interpreted because this information is also not given in the judge instruction. How the judge interpretes the evaluation categories is thus entirely dependent on the pre-training and fine-tuning data of Qwen2.5 and Deepseek-R1 respectively. This design follows \cite{wang2025scholarcopilot} who also do not provide their judge with interpretation suggestions.} To assess the reliability of the judge, the evaluation is performed two times, once by (1) instructing the judge to only provide a score from 0 to 5 for each evaluation dimension and (2) by additionally prompting the judge to provide reasoning for its decision before assigning each score. To achive consistent and reliable scoring, the scores for the evaluation dimensions are aggregated using Batched Self-Consistency. Specifically, the order in which the individual evaluation dimensions appear in the generation evaluation prompt is randomized every time the judge is instructed to compute a ranking and for each generated paper the judge is queried to evaluate it $m_\mono{judge}$ times. The evaluation is performed on 100 ground truth samples which are selected randomly from the generation evaluation dataset. To save time and computational resources, the text generation (by the evaluated models) is terminated early if the number of generated tokens exceeds 30k (this limit includes the abstracts/passages inserted during generation).

\textbf{Citation Recall.} The recall results of the single-step retrieval evaluation are visualized in \reffig{fig:retrieval_evaluation_masked} and \reffig{fig:retrieval_evaluation_abstracts}. Using the passage retrieval module consistently worsens the performance of ScholarCopilot (on average $-0.035\%$/$-0.027\%$ recall on the \mono{masked}/\mono{with-abstracts} datasets). However, as shown in \reftab{tab:cumulative_recall_loss}, when using the PR module the accumulated loss in recall from $k=10$ to $k=1$ is much lower compared to only using ScholarCopilot. So if given the correct document, the PR module tends to push the correct document further towards the top of the relevance ranking in comparison to the ranking computed by ScholarCopilot. This suggests that utilizing passage retrieval can improve scientific citation retrieval compared to doing retrieval solely based on abstracts.

\textbf{Reproducability.} ScholarCopilot alone is unable to reproduce the retrieval performance reported in \cite{wang2025scholarcopilot} (which is $64.8\%$/$40.1\%$ for Recall@$10$ and Recall@$1$ respectively). The authors do not explicitly state this in their paper but it seems they only used Introduction and Related Work sections to obtain the citing contexts for their evaluation dataset.\footnote{The file \mono{scholar\_copilot\_eval\_data\_1k.json} which is downloaded from \url{https://huggingface.co/datasets/ubowang/ScholarCopilot-TrainingData} when executing the official ScholarCopilot implementation -- and I assume is what they used for their evaluation -- only includes Introduction and Related Work sections.} Thus, using the \mono{IntroductionAndRelatedWork} dataset with \mono{masked} citations (see \reffig{fig:retrieval_evaluation_masked} on the left) as the evaluation setup replicates their methodology (see \cite[4.2]{wang2025scholarcopilot}) and should yield a performance similar to what is stated in \cite{wang2025scholarcopilot}. A possible cause for the lower recall on my dataset may be that ScholarCopilot overfits to their dataset. What exactly is responsible for this significant deviation in performance is left for future research.

\textbf{Recall Performance Analysis.} ScholarCopilot does not yield the best performance on contexts from Introduction and Related Work sections (which is what it was trained on) but instead shows significantly better performance on Experiment sections. This is possibly due to the fact that Experiments sections often include citations in a form similar to for example "Documents are tokenized with the same byte-pair encoding as GPT-2 (Radford et al., 2019)."\footnote{This example is taken from \cite{lewis2019bart}} where the citation is directly preceded by the name of a model, specific algorithm or otherwise meaningful entity and the cited document is the paper where this algorithm was first proposed. This makes it easier for the model to identify relevant documents: taking again the previous example, a document that is about GPT-2 and would thus be a good candidate to cite after a sequence like "Documents are tokenized with the same byte-pair encoding as GPT-2" will likely frequently use the term "GPT-2". ScholarCopilot in particular benefits from this since it only retrieves from a corpus of abstracts and an abstract typically includes the name of the algorithm/method proposed in a paper while simultaneously being less likely than for example the Introduction to name methods that are only similar to or preceding the proposed method. As shown in \reftab{tab:last_token}, the \mono{Experiments} dataset has indeed the highest percentage of cases where the token before the citation appears in the abstract of the cited paper. Note that this metric is likely influenced by some false positives where the last token is not a semantically meaningful entity but rather just a token that appears often in scientific abstracts.

\section{Generation Quality}\label{generation-evaluation}
\textbf{Quality Comparison.} The results designed to primarily assess the generation quality are shown in \reffig{fig:generation_evaluation_reasoning}. ScholarCopilot achieves higher scores in all evaluation categories, with a score of $15.5/25$ across all dimensions. Using passage retrieval only yields a total score of $14.9/25$ ($-0.6$), falling behind most in \mono{Background Completeness} and \mono{Academic Rigor}. This suggests that passage retrieval is not suited to improve the generation quality of academic text generation with citations. 

\begin{figure}[t]
    \includegraphics[width=\textwidth, trim={1.2cm 0 1.2cm 0}, clip]{../images/plot_generation_with_reasoning.pdf}
    \caption{Comparison of the generation quality scores between ScholarCopilot (SC) with and without passage retrieval (PR) when the judge is instructed to provide reasoning for its scoring.}\label{fig:generation_evaluation_reasoning}
\end{figure}

\textbf{Evaluation Reliability.} Instructing the judge to provide reasoning for its generation quality assessment yields ranking scores with a mean difference of $0.11$ between the scores achieved with versus without passage retrieval. Using a prompt that does not instruct the model to reason about its decision results in a much smaller mean difference of $0.01$ ($-0.1$, see also \reffig{fig:generation_evaluation_scores}). This makes it more difficult to identify key strengths and weaknesses of the evaluated methods. Furthermore, as shown in \reffig{fig:generation_evaluation_std} the standard deviation of the individual ranking scores for each evaluation dimension when instructing the judge $m_\mono{judge}$ times to rank the same generated sequence is on average significantly higher ($2.35$ compared to $2.14$ ($-0.21$) with reasoning). These results indicate that the judge is more uncertain in its evaluation when not forced to reason about its scoring. It is also important to note that the scores computed by the judge don't always align well with human judgement, an example of this is shown in \refsec{bad-generation-evaluation-example}.
