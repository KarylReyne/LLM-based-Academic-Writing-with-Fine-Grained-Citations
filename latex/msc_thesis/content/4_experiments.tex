\chapter{Experiments}\label{experiments}

\section{Evaluation Methodology}
The main focus of this thesis is it to determine how the use of the passage retrieval module affects the retrieval accuracy and generation quality of ScholarCopilot. ScholarCopilot retains its original backbone model \mono{Qwen2.5-7B} \cite{an2024qwen2}. Since the retriever of the passage retrieval module is implemented with Batched Self-Consistency, it is required to follow multiple permutations of the same instruction during inference reliably and consistently (see \cite{korikov2025batched}). Instruction tuned models, that is, LLMs that are fine-tuned on (\mono{instruction}, \mono{desired-output}) pairs, are more successful at following instructions closely rather than just minimizing the next token prediction error \cite{shengyu2025instruction}. To make use of this, the PR module uses the instruction-tuned variant of the Qwen2.5 model, \mono{Qwen2.5-7B-Instruct} \cite{an2024qwen2}, as the passage retriever. Even though it has been shown that instruction tuned models may not fully utilize given instructions and are instead just good at learning the specified output format \cite{kung2023followInstructions}, this ability alone is valuable enough for the automated parsing of an LLMs' response to justify using an instruction tuned model (especially when using Batched Self-Consistency which greatly increases the number of responses that need to be parsed).

\section{Single-Step Retrieval}\label{retrieval-evaluation}
With ScholarCopilot as baseline, I evaluated the impact of using the PR module on the retrieval performance for a variety of retrieval contexts. To this end, I introduce the \emph{single-step retrieval} task which aims to assess the models accuracy when resolving a single \mono{[RET]} token during generation. This task closely follows the evaluation methodology used by \cite{wang2025scholarcopilot}. For each of the section groups (\mono{IntroductionAndRelatedWork}, \mono{Methods}, \mono{Experiments}, and \mono{Conclusion}), $1$k randomly selected samples are used for the evaluation. Single-step retrieval is evaluated using the Recall@$k$ metric, which is given as the fraction of cases where the ground truth document appears in the top-$k$ retrieved documents \cite{wang2025scholarcopilot}. As outlined in \refsec{dataset}, the model is given the left-hand context of a citation drawn from an existing paper, together with the cited document as the ground truth. A retrieval token is appended to this context before the resulting sequence is passed to ScholarCopilot, causing the model to compute a representation of the \mono{[RET]} token based on the given context. This representation is then used to compute a distribution over the ScholarCopilot retrieval corpus that measures the relevance of each document in the corpus to the given context. When evaluating standart ScholarCopilot, the $k$ most relevant documents according to this distribution are compared to the ground truth, otherwise the top-$k_{SC}$ most relevant documents are passed to the passage retrieval module (for the reported results I use $k_{SC}=2k$, see also \refsec{hyperparameters}). For each of the top-$k$ ranked passages the PR module returns the document from which each passage was taken. These $k$ documents are then compared to the provided ground truth. 

Additionally, I evaluated two different strategies for replacing other citations that appear in the citing context. Other citations are either (1) masked using a \mono{[MASK]} token, this is also how \cite{wang2025scholarcopilot} handle citations, or (2) replaced with the abstract of the cited paper, which is done to imitate the generated context the retriever would be given during inference when the model encounters a \mono{[RET]} token. Following the setup in \cite{wang2025scholarcopilot}, the given citing context is not truncated when passed to ScholarCopilot.\footnote{\cite{wang2025scholarcopilot} only use the last sentence of the context when evaluating their baseline models (\mono{BM25} and \mono{E5-Mistral-7B-Instruct}) but use the full context when evaluating ScholarCopilot.} However, I found that passing the entire context to the PR module reduces performance, thus only the last $w$ tokens of the citing context are used when the PR retriever is prompted to rank a given set of passages.

Using the passage retrieval module consistently worsens the performance of ScholarCopilot (on average $-0.035\%$/$-0.027\%$ recall on the \mono{masked}/\mono{abstracts} datasets). However, as shown in \reftab{tab:cumulative_recall_loss}, when using the PR module the accumulated loss in recall from $k=10$ to $k=1$ is much lower compared to only using ScholarCopilot.

\textbf{Reproducability.} ScholarCopilot alone is unable to reproduce the retrieval performance reported in \cite{wang2025scholarcopilot} (which is $64.8\%$/$40.1\%$ for Recall@$10$ and Recall@$1$ respectively). The authors do not explicitly state this in their paper but it seems they only used Introduction and Related Work sections to obtain the citing contexts for their evaluation dataset.\footnote{The file \mono{scholar\_copilot\_eval\_data\_1k.json} which is downloaded from \url{https://huggingface.co/datasets/ubowang/ScholarCopilot-TrainingData} when executing the official ScholarCopilot implementation -- and I assume is what they used for their evaluation -- only includes Introduction and Related Work sections.} Thus, using the \mono{IntroductionAndRelatedWork} dataset with \mono{masked} citations (see \reffig{fig:retrieval_evaluation_masked} on the left) as the evaluation setup replicates their methodology (see \cite[4.2]{wang2025scholarcopilot}) and should yield a performance similar to what is stated in \cite{wang2025scholarcopilot}. A possible cause for the lower recall on my dataset may be that ScholarCopilot overfits to their dataset. 

\textbf{Qualitative Analysis.} Surprisingly, ScholarCopilot does not yield the best performance on contexts from Introduction and Related Work sections (which is what it was trained on) but instead shows significantly better performance on Experiment sections. This is possibly due to the fact that Experiments sections often include citations in a form similar to for example "Documents are tokenized with the same byte-pair encoding as GPT-2 (Radford et al., 2019)."\footnote{This example is taken from \cite{lewis2019bart}} where the citation is directly preceded by the name of a model, specific algorithm or otherwise meaningful entity and the cited document is the paper where this algorithm was first proposed. This makes it easier for the model to identify relevant documents. Taking again the previous example, a document that is about GPT-2 and would thus be a good candidate to cite after a sequence like "Documents are tokenized with the same byte-pair encoding as GPT-2" will likely also frequently use the term "GPT-2". ScholarCopilot in particular benefits from this since it only retrieves from a corpus of abstracts and an abstract typically includes the name of the algorithm/method proposed in a paper while simultaneously being less likely than for example the Introduction to name methods that are only similar to or preceding the proposed method. As shown in \reftab{tab:last_token}, the \mono{Experiments} dataset has indeed the highest percentage of cases where the token before the citation appears in the abstract of the cited paper. Note that this metric is likely influenced by some false positives where the last token is not a semantically meaningful entity but rather just a token that appears often in scientific abstracts.

\textbf{Correct Retrieval Overlap.} As shown in \reftab{tab:successful_retrieval_overlap}, the PR module sometimes retrieves the correct document despite ScholarCopilot being previously incorrect, especially for low $k$ (when using Recall@$k$ as measure for correctness). This suggests that the PR module has the capacity to further improve citation retrieval compared to only utilizing ScholarCopilot. The fact that the performance improvement is more prevalent for small $k$ (and consequently small $k_{SC}$ which directly influences the number of candidate passages) also indicates that the PR module may yield better performance if given fewer passages. Furthermore, the PR module tends to produce very confident relevance judgements with low variance for the top most relevant passages, this also suggests that the model struggles to differentiate between the passages it identified as being relevant.
