\section{Retrieval-Augmented Generation}\label{rag-intro}
Retrieval-Augmented Generation \cite{lewis2020retrieval} models are designed to generate text that is grounded in real-world factual knowlege. They have been widely adopted for knowledge-intensive NLP tasks \cite{shao2025reasonir} such as long-form question answering \cite{xia2024ground}, scientific question answering \cite{lala2023paperqa} and question synthesis \cite{xu2024kiwi}, generation with sentence-level citations \cite{zhang2024longcite, xia2024ground} or academic text generation \cite{asai2024openscholar, wang2025scholarcopilot}. RAG models usually consist of a generator, a pre-trained sequence-to-sequence (seq2seq) model (e.g. a Transformer-based \cite{vaswani2017attention} decoder), and a retriever with access to a retrieval corpus, which may be implemented as a dense vector index for efficient retrieval (e.g. a HNSW \cite{malkov2018efficient} index) \cite{lewis2020retrieval}. The generator uses the information retrieved by the retriever to inform its generation (as opposed to only relying on the world knowledge encoded in its pre-trained parameters). The initially proposed RAG architecture is briefly introduced in \refsec{rag-method}. Such models combine pre-trained paramentric memory with non-paramentric (retrieval-based) memory \cite{lewis2020retrieval}, which has a number of benefits: while neural language models are able to store a substantial amount of world knowledge in their parameters \cite{roberts2020much}, this knowledge can't easily be modified, expanded or directly be used to gain insight into their decision-making process \cite{lewis2019bart}. By using an external retrieval corpus, the knowledge RAG models use to inform their generation can directly be inspected, interpreted \cite{lewis2020retrieval} and modified (for example to curate the available information to only include high-quality peer-reviewed scientific documents). This interpretability allows the addition of source attribution -- precise citations referencing human-readable documents in the retrieval corpus -- to the generated text. Such attribution both reduces the models tendency to hallucinate \cite{saxena2024attribution,qian2024capacity}, increases their faithfulness to the retrieved informantion \cite{zhang2024longcite} and allow post-generation factuality assessment and correction \cite{slobodkin2024attribute}. This makes RAG-derived architectures particularly useful for knowledge-intensive tasks in NLP, such as academic writing.


\section{RAG for Scientific Writing}\label{rag-scientific-writing}
Previous work on text generation with citations has recently transitioned from treating retrieval and generation as seperate processing stages (e.g. \cite{slobodkin2024attribute}) to alternating between the two (e.g. \cite{xia2024ground}, \cite{asai2024openscholar}). \emph{Attribute First, then Generate} \cite{slobodkin2024attribute} initially retrieves a set of relevant sub-sentence spans which are then grouped into coherent clusters which in turn are used to inform an iterative sentence-by-sentence generation step \cite{slobodkin2024attribute}. \emph{ReClaim} \cite{xia2024ground}, more specifically the \emph{ReClaim with Interleaving Generation} method, is used to generate an output sequence $\mathcal{O}=\{r_1,c_1,r_2,c_2,...,r_n,c_n\}$ of alternating references and claims where claim $c_i$ is the portion of the models response that was generated based on reference $r_i$. Claim and reference generation is performed by seperate LLMs specifically trained for their corresponding task \cite{xia2024ground}. In contrast, \emph{OpenScholar} \cite{asai2024openscholar} first retrieves and reranks a set of papers $P$ relevant to the given query. These papers inform a subsequent generation step that produces a generated response $r_i$ \cite{asai2024openscholar}. This response is refined through iterative \emph{self-feedback} where during each iteration of the feedback loop $F=f_1,f_2,...,f_T$, the generator model generates sentences $f_j$ that describe potential improvements to the response and may also prompt the retrieval pipeline to retrieve additional papers, should $r_i$ require more information to generate an improved response $r_{i+1}$ \cite{asai2024openscholar}. Depending on the size of $P$ and the choice of $T$, OpenScholar still performs retrieval and generation largely seperately.

In contrast to these methods, ScholarCopilot triggers the retrieval of single references during continuous generation (see \refsec{scholarcopilot}). This allows the attribution of single sentences or even subsentence spans in the generated output, similar to \cite{xia2024ground,slobodkin2024attribute}. The model fails however, to support the same fine granularity in the cited content as it can only cite entire papers and unlike for example \cite{zhang2024longcite} is incapable of citing individual sections or even smaller spans in scientific papers. The passage retrieval module (see \refsec{passage-retrieval}) seeks to overcome this limitation.
